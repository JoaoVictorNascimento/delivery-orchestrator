# Contributing

The project is in design and discovery. Discuss substantial changes in an issue before implementing them. Use English for public documentation, issues and commit messages. Keep changes focused and explain the problem, alternatives and tests. Follow existing conventions; update requirements or ADRs when behavior changes.

Never contribute proprietary material, credentials, internal rules or real customer data. Use synthetic fixtures. Confirm you have rights to contribute under the existing repository license. Do not run tests against corporate repositories without authorization.

Implementation contributions should include relevant contract, unit or integration tests and truthful verification evidence. No claim of passing tests without execution. Do not weaken quality checks to obtain a passing build.
