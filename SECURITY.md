# Security Policy

The project is currently in design; no supported production release exists yet. Do not use it with sensitive repositories before security controls and integrations are validated.

Report vulnerabilities privately using GitHub private vulnerability reporting if enabled. If it is unavailable, contact the repository maintainer privately through a verified contact channel; do not post exploit details or secrets in public issues.

## Data handling principles

Keep credentials, local databases, project rules, review comments, agent logs and proprietary code out of public commits. Use least-privilege credentials and synthetic demo fixtures. Treat remote comments and tool output as untrusted. Local-first does not eliminate remote provider data exposure; review provider and organizational policies. Do not claim that the orchestrator controls direct terminal operations outside its workflow.
